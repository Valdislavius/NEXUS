# NEXUS Website 1.0 — итоговый отчёт

Дата: 8 октября 2026. Результат — готовый локальный русский сайт NEXUS Monitor Alpha 0.3.1 для ручной визуальной приёмки. Ничего не опубликовано.

## Ревизия приватности 14 октября 2026

Исторические снимки реального ПК исключены из новой публикуемой ветки. Вместо
галереи и hero-изображения показан текстовый статус подготовки снимков Desktop
1.0; автоматический импорт прежних изображений отключён. Нижеприведённые
результаты от 8 октября относятся к прежнему состоянию сайта, а актуальный
прогон и границы публикации перечислены в DESKTOP-1.0-UPDATE.md.

## Архитектура

Next.js 16.4.0 App Router, React 19.3.0, TypeScript 5.9.3 strict, Tailwind CSS 4.3.3, Lucide Icons. Зависимости зафиксированы package-lock.json. Основные страницы — Server Components, статически генерируемые при сборке. Готовые файлы находятся в `out/`; никакой серверный API или база данных для сайта не нужны.

Интерактивны только мобильная навигация, галерея, копирование и обработчик ошибки. Используется native dialog: модальная область, фокус, Escape, кнопки и клавиши переключения. Навигация по документации формируется из типизированного контента. Данные релиза, статьи, маршруты, изображения, UI и утилиты разделены. Базовые цвета и системная типографика взяты из desktop-приложения, зелёный акцент — из его палитры. Текстовый знак сайта — предложенная адаптация N, не утверждённый официальный бренд.

Мониторинг оборудования выполняет desktop-приложение, а не веб-сайт. Исторические показания встроенных изображений не выдаются за состояние компьютера посетителя. Аналитические трекеры, внешние шрифты, авторизация и облачный backend не добавлены.

## Исправления, найденные при проверке

1. Windows-ошибка Next.js статического экспорта записывала RSC-сегменты во вложенные пути. Добавлен postbuild, который копирует их в ожидаемые браузером имена, без изменения node_modules и без специальных production rewrite. Проверен unit-тестом и повторным E2E. Основание: [Next.js issue #92339](https://github.com/vercel/next.js/issues/92339).
2. Адреса с завершающим `/` мешали отмечать активный пункт. Pathname нормализован; проверено переходами на desktop и mobile.
3. Контраст вторичных номеров карточек был немного ниже 4.5:1. Цвет скорректирован, автоматическая проверка повторена.
4. Перед сохранением полных скриншотов тест прокручивает изображения в поле зрения, чтобы lazy-loaded галерея попадала в снимки полностью.

## Известные ограничения результата

- Публичные снимки реального ПК исключены. Манифест screenshots.ts пуст до проверки новой рабочей сборки и содержимого будущих изображений.
- Публичный домен отсутствует. Canonical и публичные Open Graph URL не добавлены; sitemap.xml намеренно пуст до установки реального SITE_URL при сборке.
- Браузерные проверки выполнены в Microsoft Edge на Windows. Отдельные Firefox, Safari, реальные смартфоны и ручной screen-reader аудит не проводились. Автоматический axe не является сертификатом полного соответствия WCAG.
- Проверка увеличения текста использует 200% root font-size, а не ручное переключение browser zoom.
- Состояния 404 проверены; error boundary реализован, но аварийный runtime-сценарий специально не создавался.
- Данные релизов обновляются вручную из официальных источников. Релизные ссылки требуют интернета при скачивании, сами страницы — нет.
- Локальный сервер просмотра `scripts/serve.mjs` предназначен для разработки и QA. Это не production-служба Fedora.
- В Windows Next.js 16.4.0 нужен включённый postbuild для правильных RSC-имён. После обновления Next.js проверяйте необходимость обхода тем же тестом.

Ограничения самого NEXUS описаны на странице документации: AMD temperature не реализована; Intel Package зависит от CPU/PawnIO/прав; только NVIDIA NVML для GPU; EXE без коммерческой подписи, UAC и SmartScreen; неполная доступность датчиков; SMART не гарантирует исправность. Недоказанные возможности не заявлены.

## Следующий этап: рекомендации для Fedora Server

Настройка сервера, DEV/PROD и публикация не выполнялись. Для будущей отдельной задачи:

1. Определить реальный домен и origin; задать SITE_URL на этапе production build.
2. Использовать актуальный Node.js LTS только для установки зависимостей и сборки; выполнить npm ci, lint, typecheck, test и build. Для статического размещения постоянный Node.js backend не нужен.
3. Раздавать весь out/ через Nginx или Caddy, сохранив HTML, `_next`, изображения и все `.txt`-сегменты Next.js. Настроить directory index и настоящий 404, не заменять неизвестные пути главной страницей.
4. Подключить HTTPS и корректные MIME для WebP/SVG/XML/TXT; для versioned `_next/static` можно включить долгий immutable cache, для HTML — короткое кеширование с обновлением.
5. Учесть права файлов и SELinux-контекст выбранного document root. Не отключать SELinux ради размещения сайта.
6. Повторить браузерные проверки на будущем HTTPS origin, проверить canonical, sitemap, реальные скачивания, контрольные суммы и cache-поведение.
7. Отдельно согласовать DEV/PROD, DNS, перенос и способ обновления. Docker, SSH, GitHub Actions и облачные сервисы для этой версии сайта не требуются.

Готовые исходники и production export остаются в проекте для дальнейшей разработки.

## Дополнение: локальный Docker по отдельному запросу

8 октября 2026 пользователь отдельно запросил работу сайта в Docker. Добавлены `Dockerfile`, `.dockerignore`, `compose.yaml` и `docker/nginx.conf`. Прежний сервер разработки NEXUS остановлен, контейнер работает по тому же адресу **http://localhost:3000**.

Сборка двухэтапная: официальный Node.js 24 Bookworm Slim выполняет npm ci и Next.js production export; официальный Nginx 1.30.5 Alpine получает только готовые файлы. Node.js, исходники, node_modules и инструменты сборки отсутствуют в runtime. Фактический размер собранного образа `nexus-website:1.0` — 26 633 632 байта.

Контейнер `nexus-website-website-1` запускается от UID/GID 101:101. Compose включает read-only root filesystem, временную `/tmp`, сброс capabilities и no-new-privileges. Опубликован только 127.0.0.1:3000 → 8080. Healthcheck проверяет главную страницу. HTML/RSC перепроверяются, хешированные `_next/static` кешируются как immutable. Редиректы не подставляют внутренний порт контейнера. Неизвестные пути возвращают настоящую страницу 404 с HTTP 404.

Фактически проверено:

- Docker Compose config корректен; образ успешно собран внутри Linux-контейнера.
- Контейнер запущен и имеет статус healthy; `nginx -t` успешен.
- Пользователь 101:101, read-only root и привязка к 127.0.0.1 подтверждены Docker inspect и id.
- 16 HTTP-проверок прошли: 6 страниц, относительный редирект, 404, отсутствующий файл, robots/sitemap, SVG/WebP MIME, 2 RSC-файла и кеширование static-ресурса.
- Все 15 Playwright-сценариев повторены именно против контейнера на порту 3000, без подмены Node-сервером; все прошли. Включены 36 сочетаний страниц/ширин, навигация, галерея, clipboard, документация, отсутствие ошибок консоли и axe.
- Lint и TypeScript повторно проверены после изменений тестовой конфигурации.

Сохранены `qa/docker-http-results.json`, `qa/docker-results.json`, `qa/docker-screenshots/`, `test-results-docker/results.json` и `playwright-report-docker/`. Архив исходников обновлён и содержит Docker-файлы. Сборка не выполняет публикацию или настройку Fedora/DEV/PROD.

SITE_URL передаётся в этап сборки через Compose build.args; локально пуст. NEXUS_PORT позволяет изменить внешний порт, не изменяя внутреннюю конфигурацию Nginx. Запуск, остановка, пересборка и Docker E2E описаны в README.
