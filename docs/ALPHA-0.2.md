# NEXUS Desktop — Alpha 0.2

Продолжение существующей версии 0.1. Стек и границы компонентов сохранены: React/TypeScript → команды и события Tauri 2 → Go sidecar через stdin/stdout. Публичного HTTP-сервера нет. Общая модель и ядро сборщика не зависят от Windows; реализован только Windows-адаптер.

## Изменения

- Единые цветовые токены: почти чёрный фон, серые поверхности, бледно-розовый и фиолетовый акценты. Жёлтый, красный, зелёный и синий используются для состояний. Контраст основного/вторичного текста на всех основных поверхностях не ниже 14,88:1 / 7,47:1; акцентов — 7,19:1.
- Более крупные показатели и подписи. Одинаковая высота карточек: 268 px, в узком окне — 264 px. Независимые панели раскрываются после соответствующей строки. CPU: характеристики рядом с сеткой загрузки потоков; GPU: компактная сетка датчиков; RAM: карточки модулей; диски: характеристики/тома и двухколоночный SMART.
- GenuineIntel отображается как Intel; U3E1 скрывается без попытки угадать сокет. Корректные сокеты сохраняются. Разделы названы «Раздел 1/2/3» по индексу Windows; технические идентификаторы оставлены в подробностях. Назначение разделов не предполагается.
- Коды критических предупреждений NVMe расшифровываются текстом; прогноз SATA — словами. В интерфейсе поясняется, что отсутствие предупреждений SMART не гарантирует исправность.
- Удалены частоты отдельных потоков: API Windows не измеряет их эффективную частоту достоверно. Общая сообщаемая Windows частота сохранена с пояснением источника.
- При сбое чтения томов прежние динамические значения сбрасываются. При остановке/задержке сборщика текущие показатели заменяются на «Нет данных». Неподдерживаемые датчики не предлагаются пользователю.
- Сохранены все фильтры, интервал 2/5/10 секунд, повторное обнаружение оборудования, офлайн-работа и локальный IPC.

## Фактические проверки

- Vitest: 14 тестов в 4 файлах — успешно. Включены независимое раскрытие, обновление данных без потери состояния, фильтры, настройка интервала, ошибки, временная потеря датчиков, остановка сбора, сокет и SMART.
- TypeScript и production frontend: успешно. Go test ./... и go vet ./...: успешно.
- Реальный сборщик: три снимка с 8 компонентами без предупреждений, завершение по EOF с кодом 0.
- Реальный IPC: 5 снимков, переход с 2 на 5 секунд; фактические интервалы 2014/5015/5015/5017 мс, команда stop завершает процесс с кодом 0.
- Браузерная проверка того же React-интерфейса на записанных реальных показаниях: 600, 900, 1280 и 1600 px. Нет горизонтального переполнения; высоты всех карточек совпадают. Проверены независимое раскрытие CPU/GPU/RAM, накопители, все фильтры, сеть и выбор 5 секунд. Ошибок браузерной консоли не обнаружено. Этот preview не входит в production-сборку.

## Температура CPU и ограничения

На проверенном процессоре Intel готового WMI-источника LibreHardwareMonitor нет (пространство имён отсутствует). Драйвер PawnIO уже присутствует, но сам по себе не предоставляет приложению готовое показание CPU: требуется отдельная интеграция низкоуровневых модулей и проверка на оборудовании. В эту итерацию она не включена. Температура ACPI не выдаётся за температуру CPU. Основная карточка CPU сохраняет ядра/потоки; фиктивных температур нет. Драйверы и настройки оборудования не устанавливались и не изменялись.

Основание для исследования: официальный [журнал выпусков LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases), описывающий использование и обновления PawnIO. LHM/.NET в приложение не добавлены.

Другие ограничения: Windows x64; Linux/macOS пока не реализованы. Набор датчиков зависит от оборудования и доступных штатных API/драйверов; GPU-датчики на этом ПК получены через NVIDIA NVML. SMART, температура дисков и свободное место опрашиваются раз в 30 секунд. Проверен один компьютер, разные DPI и чистая установка Windows не проверялись. Требуется установленный WebView2 Runtime; установщик не скачивает его. История и настройки сеанса не сохраняются.
