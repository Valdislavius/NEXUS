# SATA SMART — Alpha 0.3.1

Дата проверки: 8 октября 2026 г. Контракт JSON остаётся version=1. Поле компонента `smart` добавлено без изменения существующих метрик. Для каждого атрибута передаются отдельные Current, Worst, Threshold, Flags, точный RAW48 в десятичной строке и 12 шестнадцатеричных цифр. Отсутствующий порог остаётся null/отсутствующим. RAW не является универсальным процентом здоровья.

Это исторический отчёт Alpha 0.3.1, обезличенный для импорта исходников в Git. Конкретные модели тестовых накопителей и индивидуальные аппаратные показания удалены. Таблицы поддерживаемых семейств, ID атрибутов, разрядности и единицы остаются справочником протокола и искусственных тестовых данных. Опубликованный релиз Alpha и его архивы не изменяются.

## Источники и команды

Основной путь — синхронный [IOCTL_ATA_PASS_THROUGH](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddscsi/ni-ntddscsi-ioctl_ata_pass_through) с [ATA_PASS_THROUGH_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddscsi/ns-ntddscsi-_ata_pass_through_ex). Размер и смещение ULONG_PTR соответствуют архитектуре Windows. Дескриптор требует GENERIC_READ | GENERIC_WRITE по условиям API, но адаптер допускает только IDENTIFY DEVICE (EC), SMART READ DATA (B0/D0) и необязательное чтение старых порогов (B0/D1). Только DATA_IN, один сектор, таймаут команды 3 секунды. Изменяющие команды, включение SMART, тесты диска, запись журналов и произвольные taskfile запрещены кодом. Дескриптор закрывается на каждом выходе, повторов внутри чтения нет.

Данные SMART принимаются после проверки размера 512 байт, контрольной суммы, версии таблицы, уникальных ненулевых ID. Ответ ATA дополнительно проверяется на короткую передачу, неправильные смещения, BSY/DRQ/ERR/DF. SMART, отключённый самим накопителем, не включается приложением. Ошибка необязательных порогов не уничтожает корректные атрибуты.

Резервный путь использует уже существующий [IOCTL_STORAGE_PREDICT_FAILURE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddstor/ni-ntddstor-ioctl_storage_predict_failure): его [VendorSpecific[512]](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddstor/ns-ntddstor-_storage_predict_failure) проверяется тем же декодером только при шине ATA/SATA. Такое чтение ATA SMART без административного доступа также реализовано в первичном [Windows backend smartmontools](https://github.com/smartmontools/smartmontools/blob/master/smartmontools/os_win32.cpp). Код smartmontools в NEXUS не переносился. Имя модели берётся из [STORAGE_DEVICE_DESCRIPTOR](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddstor/ns-ntddstor-_storage_device_descriptor); серийный номер не декодируется. Этот путь не предоставляет пороги или подтверждение вращающегося носителя.

Нативный ATA passthrough не отправляется USB, RAID, SCSI и неизвестным контроллерам. NVMe использует прежний STORAGE_PROTOCOL_SPECIFIC_DATA и SMART/Health log. Температура Windows Storage сохраняет приоритет над температурой ATA; ошибка ATA не удаляет доступную температуру Windows. Нулевой прогноз сбоя означает лишь отсутствие предупреждения устройства в данный момент.

## Поддерживаемые интерпретации

Интерпретация выбирается по полной модели, а не только по производителю или ID. Все остальные атрибуты показаны без придуманного имени, единицы, процента или состояния диска.

| Семейство | ID | Представление |
| --- | --- | --- |
| Samsung SSD 840/850/860/870 EVO/PRO/QVO с подтверждённым совпадением имени | 09, 0C | RAW: часы под питанием, циклы питания |
| Samsung | 05, B3, B5, B6, BB, C7 | Переназначения, резервные блоки, ошибки NAND/чтения/CRC |
| Samsung | B1 | RAW Wear Leveling; Current/Worst показаны отдельно, без процента здоровья |
| Samsung | BE, F1 | Текущая температура из RAW byte 0; записи хоста RAW × 512 байт |
| Crucial MX100/MX200/MX300/M550, полная модель CT…SSD… | 05, 09, 0C, AD, AE | Блоки NAND, часы, включения, средний износ, отключения |
| Crucial указанного семейства | BB, C5, C6, C7, C2 | Ошибки/ECC/CRC; температура из RAW bytes 0–1 |
| Crucial указанного семейства | CA, F6 | Ресурс NAND из нормализованного Current 0…100; записи в LBA без перевода в байты |
| Kingston A400/Q500/KC600/UV500, полная модель из ограниченного профиля | 09, 0C, E7 | Часы, включения; нормализованный индикатор ресурса 0…100 без универсального процента |
| WD HDD: WDC WD… и подтверждённая вращательная скорость IDENTIFY | 05, 0C, C5, C6, C7, F1 | Переназначения RAW low16, включения, нестабильные/неисправимые секторы, CRC, LBA |
| Любой ATA/SATA с корректной таблицей | Все возвращённые ID | RAW48, Current, Worst, Flags; Threshold только при корректном ответе |

Samsung F1 и B1 описаны в [официальной статье Samsung о SMART и ресурсе](https://s7d2.scene7.com/is/content/SamsungUS/b2b/resource/2016/05/31/b2b_resource_WHP-SSD-SSDSMARTATTRIBUTES-APR16J.pdf); совпадения потребительских семейств сверены с первичной [базой smartmontools](https://github.com/smartmontools/smartmontools/blob/master/smartmontools/drivedb.h). Enterprise-документация не используется для объявления процента здоровья всех Samsung SSD.

Crucial: [Micron TN-FD-22 Rev. E, документ производителя в зеркале](https://mitmachim.top/assets/uploads/files/1625487710422-tnfd22_client_ssd_smart_attributes.pdf), страницы 5–7, 16, 21, 24. CA Current означает оставшийся ресурс, RAW — использованный; C5 означает события ECC, а 05 — блоки NAND. MX500/BX500 не включены в подтверждённую область этой ревизии документа, поэтому получают RAW-таблицу. M500 с зависимостью от версии прошивки также пока исключён из семантического профиля.

Kingston: [официальные определения SMART](https://media.kingston.com/kingston/pdf/SMART-attribute.pdf) и [описание нормализованного E7 в гарантии](https://www.kingston.com/en/company/warranty). F1 не переводится в байты: у различных Kingston единицы и расширение RAW отличаются. Для A400 применяется только ограниченный набор понятных счётчиков и нормализованный индикатор.

WD: [официальная таблица WD SMART](https://support-en.wd.com/app/answers/detailweb/a_id/12163). Единицы 09 не предполагаются универсальными часами; WD SSD не получает интерпретации HDD. RAW low16 для 05 сверено с первичным декодером smartmontools. Нет вывода о скором отказе по одному счётчику.

## Проверки и обезличенные аппаратные наблюдения

Модульные проверки охватывают закрытый список команд, размеры структуры для 32/64 бит, повреждённые/короткие ответы, ATA ABRT с одним заголовком, ошибки Win32, контрольную сумму, дубликаты ID, точность RAW48, различия производителей, пороги null, корректный нулевой счётчик, недопустимую нулевую температуру, закрытие handle, отсутствие повтора после отказа, сброс старых значений и восстановление после ошибки. NVMe-декодер и старый composite temperature проверены отдельно.

В исторической проверке Alpha выполнены штатные чтения на тестовых SATA- и NVMe-накопителях. Ниже сохранены только результаты доступности источников; модели, температуры, наработка и значения SMART-счётчиков исключены:

| Устройство/путь | Результат |
| --- | --- |
| Тестовый SATA, Windows Storage fallback | Получена корректная таблица SMART и доступно чтение температуры. Индивидуальные численные показания не публикуются. |
| Нативный ATA_PASS_THROUGH текущим процессом | Открытие read/write отклонено WIN32_5; повышенный нативный путь на устройстве не подтверждён |
| Тестовый NVMe, прежний протокольный путь | Чтение SMART сохранено. Модель и индивидуальные численные показания не публикуются. |
| Crucial, Kingston и WD HDD | Проверены только искусственными данными; физическое подтверждение отсутствует |

Эти наблюдения не фиксируют текущее состояние накопителей и не подтверждают исправность оборудования. Справочные профили и искусственные ответы проверяются модульными тестами. Аппаратный тест opt-in: NEXUS_HARDWARE_TESTS=1, затем `go test ./internal/platform -run '^TestDiskHealthHardware$' -v -count=1` в collector. В обычных unit-тестах физические устройства не опрашиваются. Необезличенные аппаратные журналы в этот документ не включаются.

## Ограничения и следующая версия

Windows Storage может возвращать данные, кэшированные драйвером; самостоятельные записи для принудительного обновления не выполняются. Старый D1 может не поддерживаться. RAW48 сохраняет стандартные шесть байт; нестандартные расширения атрибутов до 56/64 бит не интерпретируются. USB SAT, RAID и vendor-specific miniport намеренно не добавлены без отдельных проверенных безопасных адаптеров. Семантика неизвестных прошивок/семейств остаётся неизвестной.

Каждый refresh заменяет RAW-таблицу, сбрасывает старые значения в null при ошибке и оставляет актуальную причину. Доступ, контроллер, неподдерживаемость, некорректный ответ и временные ошибки имеют отдельные категории и ограниченные коды. Журнал stderr содержит только номер диска, категорию и код; не серийный номер, путь или исходный текст ошибки. Отказ чтения не инициирует изменение системных настроек.

Следующий этап: физические проверки повышенного ATA пути и других контроллеров; таблицы прошивок MX500/BX500/Kingston; проверенная интерпретация расширенных RAW; подтверждение единиц записи для дополнительных моделей. Добавлять профили следует вместе с документацией производителя и физическими образцами, сохраняя безопасный отказ.
