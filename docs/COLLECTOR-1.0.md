# Collector Desktop 1.0

Collector остаётся отдельным Go-процессом с построчным JSON через stdin/stdout.
Совместимость Alpha 0.3.1 сохранена: `version: 1`, идентификаторы компонентов,
метрик и единицы не изменены. Привилегированный доступ к CPU не расширен.

## Разделение обязанностей

- `internal/model`: нормализация, корректность значений, доступность и срок годности.
- `internal/core`: жизненный цикл, команды, ограниченные интервалы и отмена.
- `internal/platform/profile.go`: профили частот опроса.
- `internal/platform/windows.go`: статический инвентарь и координация провайдеров.
- `performance_windows.go`: физическая память, commit, кэш и счётчики Windows.
- `network_windows.go`: кеш конфигурации и быстрые счётчики IP Helper.
- `disk_windows.go`: чтение, запись, задержки, очередь и активность дисков.
- `health_windows.go`, `ata_smart_windows.go`: имеющиеся проверенные SMART/NVMe-провайдеры.
- `cpu_temperature_*`: прежняя политика безопасного чтения CPU Package.

SQLite, диагностика, тесты оборудования и отчёты находятся за пределами Collector.
Они используют полученные метрики; Collector не запускает стресс-тестов и не
создаёт сетевого диагностического трафика.

## Аддитивный контракт

Каждая метрика содержит `id`, `label`, `value`, `unit`, `source`, `at`, `primary`
и новый `status`: `available`, `unavailable` или `stale`. Отсутствие датчика —
`value: null` и понятная `reason`; это не нулевое показание.

`maxAgeMs` задаёт допустимый возраст. Для быстрых показателей это три интервала,
для SMART и свободного места — два медленных интервала. Временная отметка `at`
сохраняет время реального чтения, включая кешированные медленные значения.
Устаревшее значение очищается; `diagnostic.code` становится `METRIC_EXPIRED`.
Статическая ёмкость диска не получает TTL. Получатель должен контролировать TTL
также при полной остановке потока снимков.

| Команда stdin | Действие |
| --- | --- |
| `{"command":"profile","profile":"economy"}` | Быстро 5 с, медленно 60 с |
| `{"command":"profile","profile":"balanced"}` | Быстро 2 с, медленно 30 с; по умолчанию |
| `{"command":"profile","profile":"detailed"}` | Быстро 2 с, медленно 10 с |
| `{"command":"interval","intervalMs":1000}` | 1 с для явно включённого оверлея |
| `{"command":"interval","intervalMs":2000}` | Совместимая команда Alpha; также 5000 и 10000 |
| `{"command":"stop"}` | Корректное завершение |

Неизвестные профили и произвольные интервалы отвергаются. Закрытие stdin
завершает процесс даже при зависшем аппаратном провайдере. Поток команд ограничен
и не препятствует обработке EOF/stop.

## Новые реальные данные и оптимизация

- RAM: `commit`, `commitLimit`, `commitPeak`, `commitLoad`, `cache`, `kernelPaged`,
  `kernelNonpaged`; прежние `used`, `available`, `total`, `load` сохранены.
  Один непривилегированный `GetPerformanceInfo` одновременно получает физическую
  память, commit, кэш и число процессов/потоков системы. Значения страниц
  переводятся в байты через реальный размер страницы.
- Диски: `readLatency`/`writeLatency` в ms на завершённую операцию, `activity` в %
  и `queueDepth`. Используется тот же ответ `IOCTL_DISK_PERFORMANCE`, который уже
  нужен для скорости: дополнительных аппаратных чтений нет. Если операций не
  было, задержка недоступна, а не равна искусственным 0 ms. Сбросы счётчиков,
  переполнение и некорректные интервалы отвергаются.
- Сеть: IP/DNS/шлюз и список интерфейсов кешируются на медленном интервале,
  заменяя прежний обход IP-таблиц на каждом быстром опросе. Между обновлениями
  читаются только счётчики известных интерфейсов. Добавлены счётчики ошибок,
  отброшенных пакетов и `activeAdapters`. При смене LUID или переходе подключения
  заново собирается база для скорости. IP/DNS/шлюзы — чувствительные данные;
  обезличенные отчёты должны исключать сетевые характеристики.
- После длительной паузы сбрасываются базы CPU/network/disk: скорость не
  усредняется по интервалу сна. Ошибка чтения памяти немедленно очищает старые
  значения. Старые логические потоки CPU не сохраняют прошлую загрузку.
- Статические CPU/SMBIOS/прошивка диска получаются при инвентаризации. Ранее
  существовавшие uptime Windows, кэши CPU и загрузка логических потоков сохранены.

Профили ограничивают опрос, но сами по себе не подтверждают достижение бюджетов
CPU/RAM или отсутствие влияния на FPS. Эти показатели измеряются отдельно.

## Проверка 14 октября 2026 года

`go test ./... -count=1 -cover`: все четыре пакета проходят, существующие тесты
сохранены. Покрытие: cmd 37.0%, core 81.8%, model 66.7%, platform 41.3%.
`go vet ./...`: успешно. `go build -trimpath -ldflags '-s -w'`: успешно.

Добавлены модульные проверки статуса/TTL, ABI Windows x64, единиц страниц RAM,
очистки ошибки памяти, задержек/активности диска, профилей и команд IPC.
Они не подменяют аппаратные проверки. Существующий тест WMI требует доступа к
реальным устройствам; в ограниченной песочнице он получает отказ, а при разрешённом
аппаратном доступе проходит.

Реальный короткий запуск новой сборки: 3 готовых снимка, 8 компонентов,
154 метрики, 142 доступных и 12 недоступных, устаревших 0, завершение `stop` с
кодом 0. Подтверждены RAM commit/cache и реальные disk activity/write latency.
Задержка диска без операций корректно оставалась недоступной. Это проверка
одного доступного ПК, а не совместимости со всем оборудованием.

## Сохраняющиеся ограничения

- AMD Package не читается небезопасными SMN/SMU/MSR-операциями. Нет безопасного
  подтверждённого провайдера — температура остаётся недоступной.
- Intel сохраняет только прежние два разрешённых MSR-чтения через PawnIO.
  Драйвер не устанавливается автоматически; нет изменений регистров.
- Данные GPU полностью доступны через существующий NVIDIA NVML. Другие драйверы,
  hotspot и показатели, которых API не возвращает, корректно недоступны.
- Датчики платы/вентиляторы/напряжения не подменяются температурой ACPI или
  вымышленными значениями; необходим подходящий безопасный провайдер.
- Доступность SMART зависит от устройства, контроллера, драйвера и прав.
- Новые сетевые интерфейсы появляются с задержкой до медленного интервала.
  Статические изменения дисков/GPU требуют повторной инвентаризации/перезапуска.
- Возможности Windows более 64 логических процессоров остаются ограниченными
  прежней политикой явного сопоставления processor groups.

[DISK_PERFORMANCE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntdddisk/ns-ntdddisk-_disk_performance),
[GetAdaptersAddresses](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getadaptersaddresses).
